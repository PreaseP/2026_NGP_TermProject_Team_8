- 검증: Debug x64 클라이언트 빌드 성공. `Character.h`의 기존 C4267 형변환 경고 1건이 표시됐다. 실행 및 서버 연동 테스트는 수행하지 않았다.
- 다음 단계는 `ProcessPacket`에서 경기 중 `S2C_ADD_OBJECT`를 `ApplyWorldPacket`에 전달하는 연결이다. 사용자 요청에 맞춰 한 단계씩 진행한다.
- 커밋과 푸시는 하지 않았다. 이전 진행 기록은 Git 이력에 있으며, 이 파일은 현재 작업 기록부터 작성했다.

## 2026-11-22 구현 — [11.23] 후속 단계: 저장된 눈덩이 화면 표시

- 사용자 요청에 따라 생성 정보 저장 다음 단계로 화면 표시를 연결했다. 눈덩이 이동·제거와 물리·충돌 계산은 이번에 구현하지 않았다.
- `GameClient.h`에 `GetObjects() const`를 추가했다. `objects`를 읽기 전용 참조로 반환하며, 화면은 이 목록에서 `OBJ_SNOWBALL`만 골라 읽는다. 패킷 송수신을 수행하는 함수는 아니다.
- `Snowball.h`에 `setPosition(const glm::vec3&)`을 추가해 기존 구 모양을 지정한 위치에 그릴 수 있게 했다. 한국어 주석이 추가되면서 발생한 C4819 경고를 해결하기 위해 원래 ASCII였던 이 헤더를 UTF-8 BOM으로 명시했다. 기존 주석·다른 소스의 인코딩은 보존했다.
- `Main.cpp`의 경기 화면 초기화에서 공용 그리기 객체 `matchSnowball`을 한 번 준비하고, `renderWorld`에서 서버가 알려 준 각 눈덩이의 `renderPos`로 위치를 바꿔 기존 `Snowball::render`를 호출한다. 여러 눈덩이가 같은 구 모양의 그래픽 자원을 재사용한다.
- 공용 객체는 속도 0, 반지름 0.15로 만들고 로컬 `update`는 호출하지 않는다. 저장된 물체 정보는 렌더링 중 변경하지 않으며, 강화 여부와 무관하게 현재는 기존 흰색 눈덩이로 표시한다. 강화 효과의 시각화는 별도 일정에 둔다.
- `ClearMatchScene`에서 공용 눈덩이를 삭제하고 포인터를 비운다. 기존 연결 종료 후 화면 전환과 `OnExit`의 그래픽 정리 경로를 재사용한다.
- 검증: Debug x64 클라이언트 빌드 성공. 새 인코딩 경고는 해결됐으며 기존 `Character.h`의 C4267 형변환 경고 1건이 남는다. 로컬 TCP 생성 패킷을 실제 `Main.cpp`의 OpenGL 출력에 연결한 테스트에서 두 눈덩이 표시, 양쪽 시점(1200×675 / 960×540)의 생성 위치 부근 픽셀 변화, 여러 프레임 동안 위치·공용 객체 유지, 연결 종료 시 데이터·그래픽 객체 정리를 통과했다.
- `.vs/Snowball1123/snowballs-0.bmp`와 `snowballs-1.bmp`를 직접 열어 각 시점의 눈덩이 두 개를 확인했다. 테스트 소스·프로젝트·이미지는 `.vs/Snowball1123`의 로컬 자료다. 실제 팀 서버의 마우스 입력 → 서버 생성까지의 전체 연동 결과는 아니다.
- `git diff --check` 통과. `Main.cpp`와 `GameClient.h`의 UTF-8 BOM 및 기존 CRLF를 유지했다. 서버·프로토콜·기존 로컬 게임의 눈덩이 처리는 변경하지 않았다. 커밋과 푸시는 하지 않았다.
